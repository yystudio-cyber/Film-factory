## 工作站资源和调度

工作台通过 HTTP 连接推理进程。主控本身不加载 torch。在 8766 运行独立控制台，使既有 8765 项目能继续打开。ComfyUI 的视频任务串行提交，GPU1 使用已验证的低显存参数；ACE-Step 使用 GPU0。两块卡各有独立的 12 GB 容量。全自动模式下，已锁定的音乐说明可交给 GPU0 与 GPU1 镜头串行生产同期执行。设置 `parallel_score: false` 可推迟到组片前，逐镜确认模式默认等待镜头采用完毕。全片明确静音则跳过配乐。

导演与场记先锁定剧本覆盖和总镜长，摄影与声音部门并发读取同一版分镜，分别给出景别／走位／切点与现场声／承接／混音意图。每组至多八镜、两个模型请求，分别检查镜号、必填字段并缓存结果。导演将部门意见带入正式提示词；修改镜头后重算相应执行单。工作站保持一个视频执行者，文本分工没有增加 GPU1 的渲染并发。分镜预演按帧展示计划、来源和剪点；启用动态草稿会实际调用另行绑定的单阶段图，先核对低分辨率动作，再执行正片图。

剧本、参考图片及中文描述可以从原 Studio 项目建立内容快照。`import-clips` 保留旧片号与已发号段，`import-studio` 迁入项目内容并可明确保留首尾帧链接。场记记录原句、对应镜号和验收要求，Qwen 根据实际参考与镜内帧、邻镜剪点图判断画面。源图、任务回执、提示词、抽帧、分项意见与采用项均可追溯。

帧时间线独立于采样帧数。长度为 T 帧的剪辑至少生成 8 × ceil((T−1)/8) + 1 帧。6 秒在 24 fps 的交付时钟上是 144 帧，生成 145 帧，只剪入前 144 帧。衔接使用第 144 帧，先提取干净画面，再叠字和图形。制作目录保留原始模型文件。成片采用整数帧时间线，逐镜解码音频去除 AAC 编码器填充，再拼接并编码总音轨。混音对有对白或旁白的镜头按实际信号避让配乐，同时尊重明确静音。最终 AAC 编码后复测节目响度与真峰值，保存处理前后测量值和增益决定。

## 状态与失败语义

| 场景 | 系统动作 |
|---|---|
| 自动模式 | 每个候选必须通过每一维的阈值。请求多版本时，从通过者中采用总分最高者。 |
| 逐镜模式 | 进入 review，等待选中同镜可用候选；批量指令仅免去指定范围的手工点选。 |
| 修改插队 | 保存修改意见，重新生成目标镜；已采用的后续镜头一并重算，保留旧媒体和片号。 |
| 模型/API 故障 | 保留远程任务号、已有采用项和错误。提交请求发生不确定结果时不会盲目重复发送 POST。 |
| 画面或媒体不达标 | 保存具体退回原因与修复意见，换种子并重写提示词；默认每种候选最多 3 次。 |
| 总审不合格 | 保存组接视频、成片联系表、验收原因。能定位到镜号时有限次回修；仍未通过则显示待处理。 |
| 异常退出或主动停止 | 重启将运行和排队中的工作标为已取消；人工继续才会重新入队。候选号和采用关系在 SQLite 中持久保存。 |

指令和采用关系通过 SQLite 事务更新；同一数据目录只允许一个调度实例。发布前再次核对运行状态、采用片号与在途修改；母版与对应的验收报告、时间线写进同一交付版本，最后再切换到 done 状态。中途停止或旧版混合文件不会被当作新成片放行。每个项目保留版本、种子与评分，便于比较不同轮次。现场声音是否贴合动作、台词表演、跨镜细微变形仍可能躲过抽样检查；阈值需用自己的已通过片和被否片校准。
